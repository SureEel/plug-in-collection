# LUFS Master

A loudness meter, live leveler and transparent true-peak limiter for Akai MPC and Force
standalone hardware, by sureeel. For mastering to a streaming/broadcast loudness target and
for live broadcast.

Runs on 32-bit (armv7) and 64-bit (aarch64) MPC and Force hardware. Needs MPC OS / Force OS 3.10.1 or later with **Preferences → Enhancements (Beta) →
Enable Enhancements** and **External Plugin Support** switched on.

## How to use it

1. Insert LUFS Master last on the track or master you want to deliver.
2. Pick a **Target** (-14 streaming, -16 Apple Music/podcasts, -23 EBU R128, -24 ATSC A/85, or
   Custom) and a **Ceiling** (default -1.0 dBTP).
3. **Mode = Measure**, then play the whole track once. The plugin stores two numbers per 100 ms
   (loudness and true peak, never audio) and rides the gain slowly so you already hear it near
   the target. The leveler holds its gain during silence and quiet passages (more than 10 LU
   below the track's own integrated loudness), so it does not pump up breaks or fades.
4. **Mode = Locked**. Switching to Locked is the Lock button. Within a moment **Gain** shows
   the fixed offset and **Predicted** the integrated loudness the bounce will have ("calc"
   while it works). No gain riding happens in Locked; the limiter is only a safety ceiling.
5. Press **Refresh**, then bounce/record. **Out Int LUFS** measures the bounce as it happens, so
   at the end it should read the target. **GR Max** shows how hard the limiter had to work.

If **Predicted** stays below the target, that loudness is not reachable on this material
without crushing it: the lock stops where one more dB of gain would add less than 0.1 LU.

**Reset** clears the stored measurement, the locked gain and every readout (start again from
Measure). **Refresh** clears only the readouts (averages, output integrated, max true peaks and
max gain reduction) and keeps the measurement and the lock.

The locked gain, the measurement data and all settings are saved with the project; reopening
a project in Locked mode uses the saved lock and does not recalculate it.

## Pages

**MASTER** (hand-drawn rack panel, `skins/`, generated by `skin_src/make_skin.py`): brushed-metal
panel; 48-LED momentary loudness bar (output, -48..0 LUFS, 1 LU per LED, green / amber from -18 /
red from -9) with its numeric value; large integrated-loudness readout (output, since Refresh)
beside the target value and its preset name (double-tap the target to change it); 24-LED gain
reduction bar (0..12 dB) with GR max; small In Int / Gain / Predicted / True peak readouts;
three lit hardware-style Mode switches (Bypass white, Measure green, Locked red); Ceiling and
Custom LUFS knobs (Custom only when Target = Custom); Reset and Refresh push buttons.
Q-Links on this page: top row Mode, Target, Ceiling, Custom; next row Reset, Refresh.
All artwork is static; the meters are pre-drawn film strips, so nothing is drawn at run time.
Meters refresh at 10 Hz, other numbers at 5 Hz. After changing `ui.json` or the layout, run
`python "plugins/LUFS Master/skin_src/make_skin.py"` before `tools/build.py`.

**METERS**: input loudness over time: 48 bars of 5 s each (the last 4 minutes of the stored
measurement, newest on the right, the last bar filling live), recorded only in Measure mode,
rebuilt from the saved measurement when a project loads, cleared by Reset. Below it every meter
as a labelled number with its unit: INPUT and OUTPUT momentary, short-term, integrated, ungated
average and true-peak max; LIMITER gain reduction, GR max, gain before limiter, predicted output
and ceiling. Parameters 20-67 ("Hist 01".."Hist 48") are the display-only history columns.

## Parameters

| # | Name | Range | Notes |
|---|---|---|---|
| 0 | Ceiling | -3.0 .. 0.0 dBTP, default -1.0 | true-peak ceiling of the limiter |
| 1 | Target | -14 / -16 / -23 / -24 LUFS / Custom | |
| 2 | Custom LUFS | -30 .. -6 LUFS in 0.5 steps | used when Target = Custom |
| 3 | Mode | Bypass / Measure / Locked | switching to Locked performs the lock |
| 4 | Reset | button | |
| 5 | Refresh | button | |
| 6-9 | In Mom / ST / Int / Avg LUFS | display | input momentary (400 ms), short-term (3 s), integrated (the stored measurement), plain ungated average since start/Refresh |
| 10-13 | Out Mom / ST / Int / Avg LUFS | display | same for the output; Out Int is since Refresh |
| 14-15 | In TP Max, Out TP Max | display | highest true peak since Refresh |
| 16 | Gain | display | gain applied before the limiter (leveler or locked offset) |
| 17 | GR | display | limiter gain reduction now (worst of the last 100 ms) |
| 18 | GR Max | display | largest gain reduction since Refresh |
| 19 | Predicted | display | Locked: predicted integrated loudness of the output |

Display parameters are not automatable. Built-in programs set only Ceiling, Target and Custom
(Streaming -14, Apple/Podcast -16, EBU R128 -23, ATSC A/85 -24 with a -2 dBTP ceiling); picking
one never changes the mode or the measurement.

## How it works

- **Meter**: ITU-R BS.1770-4 / EBU R128. K-weighting coefficients derived for the sample rate
  from the standard's analogue prototype (the libebur128 derivation), double precision.
  Integrated loudness uses 400 ms windows with 75 % overlap, -70 LUFS absolute and -10 LU
  relative gates.
- **Limiter**: one gain for both channels, applied to a 3.2 ms-delayed copy of the signal.
  Peaks are detected on a 4x oversampled copy (24-tap-per-phase Kaiser-windowed sinc). The gain
  dips into each peak along an S-shaped curve over 2.9 ms and recovers with a 150 ms release. No
  clipper, no saturation, no filtering in the audio path: when nothing is over the ceiling the
  output is the input times exactly the chosen gain. Bypass is bit-exact (same delay, so
  switching never shifts timing). Latency 140 samples is reported to the host.
- **Lock**: integrated loudness from the stored blocks gives the first offset. A block-rate model
  of the limiter (required gain reduction per block from its stored true peak, carried into the
  following blocks like the release, with a cap on how much loudness can get through a
  brickwall limiter) predicts the output loudness. The offset is refined with secant steps until
  the prediction is within 0.02 LU. The model constants were fitted to 37 renders of this
  limiter.

## Tested (desktop, before installing)

- SDK host simulator: PASS (20 passed, 0 warnings, 0 failures) at 128- and 32-frame blocks.
  Average CPU 0.46 % of a 128-frame block on a desktop CPU (the SDK's rule of thumb is ×15-25 on
  the 32-bit ARM models, so roughly 7-12 % there). Confirm with Device Info on the hardware.
- Meter against EBU-style test tones: 1 kHz at -23 and -33 dBFS read -23.0 / -33.0 LUFS; both
  gating sequences read -23.0; a sine at fs/4 with 45° phase (sample peak -9 dBFS) reads
  -5.9 dBTP (true value -6.0).
- Real songs and a synthetic drum mix, checked with pyloudnorm and a scipy 4x/8x true-peak
  measurement. Songs locked to -24, -16, -14 and -10 LUFS landed within 0.3 LU of the
  prediction (most within 0.05). Drums pushed into 11-28 dB of gain reduction landed within
  0.5 LU. Every bounce stayed at or under -1.04 dBTP (4x) with a -1.0 ceiling. Unreachable
  targets (songs pushed to -8 / -6) were reported as reachable-loudness predictions within
  0.3 LU.
- Leveler on a live-set edit with level jumps and silence: 88 % of active music within ±1 LU of
  the target, gain held through silence.
- Project save/reload restores the lock and measurement; Reset clears them; bypass is bit-exact.

## Limits and honest notes

- The readouts update when the plugin tells the host their values changed (5 times a second).
  Whether the MPC screen redraws them live could only be checked on the hardware.
- 8x true peak can sit up to ~0.2 dB above 4x on material with strong content near 20 kHz under
  very heavy limiting; the ceiling is held to the BS.1770 4x measure.
- The stored measurement holds up to 2 hours (Measure stops storing after that; the input meter
  keeps running).
- The limiter loss model was fitted on four sources; very unusual material can land a little
  further from the prediction. Out Int LUFS during the bounce always shows the true result.
- Sample rate is fixed at 44.1 kHz on the MPC; the code handles other rates for desktop testing.

## Build and test

```
python tools/build.py "plugins/LUFS Master"
.sdk-tools/host_sim "plugins/LUFS Master/build/native/lufs-master.dll" test
```

`test/wavhost.cpp` is a desktop-only test host that runs a WAV through Measure → Lock → bounce
→ project reload → Reset → Bypass and prints the readouts as the MPC shows them:

```
.sdk-tools\zigenv\Lib\site-packages\ziglang\zig.exe c++ -std=c++17 -O2 -I framework -o wavhost.exe "plugins/LUFS Master/test/wavhost.cpp"
wavhost.exe lufs-master.dll song.wav out/song --target 0 [--custom -12] [--ceiling -1] [--pregain -6] [--block 32]
```

`test/neon_shim/` lets the NEON code path run on a PC for comparison (`-D__ARM_NEON`).
